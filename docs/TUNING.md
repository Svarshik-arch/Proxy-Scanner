# Параметры для максимальной скорости

Для больших диапазонов быстрее всего режим **masscan**: он сам формирует пакеты и не ждёт
ответа на каждый. Встроенный **TCP-connect** ограничен числом одновременных подключений
и таймаутом.

## masscan

| Параметр | Значение |
|---|---|
| Скорость, пакетов/с | **50 000–100 000** для начала, при необходимости до 200 000–300 000 |
| Ожидание ответов, с | **2** в локальной сети, 3–5 для удалённых сегментов |
| Дополнительные аргументы | пусто; `--retries 1` — только если теряются ответы (скан вдвое дольше) |

- На Linux masscan быстрее, чем на Windows (Npcap ограничивает скорость сильнее).
- Реальный потолок задаёт сеть: коммутаторы, межсетевые экраны, IDS. При слишком высокой
  скорости ответы теряются — скан заканчивается быстрее, но находит меньше.
- Как подобрать: просканируйте один диапазон на 50 000 и на 150 000. Находок столько же —
  можно поднимать; меньше — снижайте.
- Оценка: /16 × 13 портов ≈ 850 000 пакетов → при 100 000 пакетов/с около 9 с плюс ожидание.

## TCP-connect

| Параметр | Значение |
|---|---|
| Параллельных подключений | **1500–2000** (максимум в программе — 4000) |
| Таймаут подключения, мс | **300–500** в локальной сети, 800–1500 для удалённых сегментов |

- Скорость ≈ подключения ÷ таймаут: 2000 / 0,4 с ≈ 5000 проверок/с; /16 × 13 портов —
  несколько минут. Дольше всего проверяются пустые адреса, где никто не отвечает.
- Слишком короткий таймаут ускоряет скан, но в медленной сети часть живых портов
  не успеет ответить.
- **Linux:** перед запуском поднимите лимит открытых файлов (`ulimit -n 65535`, см.
  [LINUX.md](LINUX.md)); скрипт `proxy-scanner.sh` делает это сам. Иначе при 1000+
  подключений появятся ошибки «Too many open files».

## Диагностика найденных узлов

| Параметр | Значение |
|---|---|
| Параллельных проверок | **64–128** |
| Таймаут, мс | **2000–3000** |

Найденных прокси обычно немного, поэтому этот этап почти не влияет на общее время.
Слишком короткий таймаут здесь вреден: медленный прокси будет помечен ошибкой.

## Что ещё ускоряет

- **Меньше портов** — время пропорционально их числу. Для поиска прокси достаточно
  `3128,8080,8000,8888,1080,3129,8081,9090`.
- **Сначала только обнаружение.** Снимите «Диагностика найденных узлов», найдите порты,
  затем нажмите «Перепроверить все».
- **По частям.** «Остановить» → «Продолжить», в том числе на другом ПК: прогресс
  сохраняется в файле сессии.

> Перед массовым сканированием на высокой скорости предупредите сетевую службу
> или службу ИБ: такой трафик похож на атаку и может привести к блокировке порта
> на коммутаторе.
