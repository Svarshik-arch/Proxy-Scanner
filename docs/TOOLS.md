# Инструменты диагностики

Кроме поиска прокси, в программе есть набор инструментов для повседневной работы
с сетью. Все они работают без интернета: корневые сертификаты берутся из системы
(в закрытом контуре это корпоративные CA), DNS по умолчанию системный, база
производителей сетевых карт (IEEE OUI, около 40 000 записей) вшита в программу.

Каждый инструмент — отдельная вкладка: слева параметры, справа результаты.
Щелчок правой кнопкой по узлу в любой таблице открывает меню «→ MTR / DNS / HTTP /
Сервисы / TLS / Узлы / Прокси» — узел передаётся в другой инструмент.
**Ctrl+K** — быстрый переход к инструменту, пресету или найденному узлу.

## Хост

Сведения об этой машине, как `ipconfig /all` + `route print` + `arp -a` +
`netstat -anob` в Windows или `ip a` + `ip r` + `ss -tunap` в Linux:
интерфейсы (адреса, шлюз, DNS, DHCP-сервер, суффикс, MTU, скорость, производитель
сетевой карты), таблица маршрутов, ARP-таблица, соединения с привязкой к процессам.
Без прав администратора/root процессы других пользователей не видны.

## MTR

Трассировка с постоянным наблюдением: по каждому хопу — потери, последнее, среднее,
лучшее и худшее время, стандартное отклонение, джиттер и график последних замеров.
Несколько адресов на одном хопе — признак балансировки (ECMP).

| Режим | Windows | Linux |
|---|---|---|
| ICMP | `IcmpSendEcho`, без прав администратора | raw-сокет (root) или ping-сокет, если разрешён `net.ipv4.ping_group_range` |
| UDP (порты 33434+) | нет | без прав (`IP_RECVERR`) |
| TCP (время подключения до узла) | да | да |

«Найти MTU пути» — пробы с запретом фрагментации: 1500, затем 9000 и двоичный поиск.
Учитываются ICMP «нужна фрагментация» (с MTU следующего участка) и молчание
(«чёрная дыра» PMTU, частая причина зависаний через VPN).

## Узлы

Обнаружение узлов в подсети (до /16): ICMP, TCP по набору портов (ответ RST тоже
считается признаком жизни — так находятся узлы с закрытым ping), ARP, NetBIOS
(имя, рабочая группа или домен, контроллеры домена, файловые серверы), mDNS,
SSDP/UPnP, обратный DNS. Для каждого узла — MAC и производитель, догадка об ОС по
TTL и портам.

ARP в Windows выполняется функцией `SendARP` (без прав). В Linux без root программа
«будит» ядро UDP-пакетом и берёт MAC из `/proc/net/arp` — работает в пределах своего
сегмента.

## DNS

Запросы в духе `dig`: любые типы записей (A, AAAA, CNAME, MX, NS, TXT, SOA, SRV, PTR,
CAA, DS, DNSKEY, RRSIG, NSEC/NSEC3, TLSA, SVCB/HTTPS, NAPTR …), несколько имён и
серверов сразу.

* Серверы: `system` — серверы из настроек системы; `10.0.0.53`, `10.0.0.53:5353`,
  `tcp://…`, `tls://…` (DoT), `https://…/dns-query` (DoH).
* Флаги: рекурсия (RD), DNSSEC (бит DO, флаг AD в ответе), CD, NSID (какой узел
  anycast ответил).
* Обрезанный UDP-ответ (TC) автоматически повторяется по TCP.
* AXFR — проверка, отдаёт ли сервер зону целиком.
* IP-адрес вместо имени — обратный запрос (PTR).
* `{domain}` в имени заменяется DNS-суффиксом машины: пресет «AD: SRV-записи домена»
  находит контроллеры, Kerberos и Global Catalog без ввода имени домена.
* «Сравнение серверов» — таблица запрос × сервер; расхождения подсвечены
  (split-horizon, подмена ответов, несинхронизированные зоны).

## HTTP

Запрос в духе `curl -v -w`: метод, заголовки, тело; напрямую или через прокси
(вход Basic, NTLM, Kerberos/Negotiate — в Windows под текущим пользователем без
пароля). Показывается время по фазам (DNS, TCP, CONNECT через прокси, TLS, ожидание
первого байта, загрузка), цепочка сертификатов и доверие к ней по системным корням,
сырые заголовки запроса и ответа, тело, цепочка перенаправлений. Подмена адреса
узла — как `curl --resolve`. Повторы — статистика разброса времени ответа.

## Сервисы

Сканер сервисов и версий по списку узлов и портов:

* TCP: баннеры (SSH, FTP, SMTP, POP3, IMAP, Telnet, VNC, MySQL/MariaDB), HTTP
  (Server, X-Powered-By, заголовок страницы, требование аутентификации), TLS на
  любом порту (версия, сертификат, срок, доверие), SMB (диалект, SMBv1,
  обязательность подписи), RDP (NLA или устаревшая защита), MSSQL (версия и год),
  PostgreSQL, Redis (с паролем или без), memcached, Elasticsearch.
* UDP: DNS (version.bind), NTP (stratum, источник и **сдвиг часов** — больше
  5 минут ломает вход в домен Kerberos), SNMP (sysDescr с заданным community),
  NetBIOS, MSSQL Browser (экземпляры и порты), SSDP, mDNS.

Кнопка «взять открытые порты из сканирования прокси» передаёт найденное в разделе
«Прокси».

## TLS

Аудит в духе testssl/sslscan по одному узлу или по всей сети:

* поддержка SSL 3.0, TLS 1.0, 1.1, 1.2, 1.3 — собственным ClientHello, поэтому
  видны и устаревшие версии, которых нет в современных библиотеках;
* перебор наборов шифров с оценкой: небезопасный (NULL, EXPORT, anon, RC4, DES),
  слабый (3DES, без PFS), допустимый, сильный; включены и шифры ГОСТ;
* цепочка сертификатов: ключ, алгоритм подписи, сроки, имена, отпечаток;
  проверка по системным корням;
* итоговая оценка: A, A-, B, F или T (цепочка не доверена) и список замечаний.

## Пресеты

У каждого инструмента есть кнопка «Пресеты ▾»:

* встроенные пресеты меняют только нужные поля (например, «Windows и AD» в сканере
  сервисов меняет только списки портов);
* «💾 Сохранить текущие настройки…» — свой пресет; цели (адреса, имена, URL) можно
  сохранить или нет; сетевые параметры машины и пароли не сохраняются никогда;
* импорт и экспорт — перенос пресетов между ПК и коллегами;
* свои пресеты хранятся в `proxy-scanner-presets.json` рядом с программой (или там же,
  где файл сессии).

Меню **«Контур ▾»** в шапке применяет общий пресет сразу ко всем инструментам:

* **Открытый контур** — публичные тестовые узлы (example.com, badssl.com,
  portquiz.net) и публичные DNS для сравнения;
* **Закрытый контур** — никаких обращений к внешним узлам: системные DNS,
  проверка качества SSL-инспекции и проверка обхода прокси выключены, пока не
  указаны свои внутренние узлы.

## Командная строка

Те же инструменты без окна — для скриптов, планировщика и удалённых сессий.

* Windows: `proxy-scanner-cli.exe` (консольная версия). Основная программа тоже
  принимает команды (`proxy-scanner.exe dns …`), но вывод в консоль у оконной
  программы ненадёжен — используйте `-o файл` или `proxy-scanner-cli.exe`.
* Linux: `proxy-scanner-cli` или `proxy-scanner <команда>`.

```text
proxy-scanner-cli <команда> [цели…] [--preset ИМЯ]… [--set поле=значение]… [--json] [-o файл]
```

| Команда | Что делает |
|---|---|
| `host` | состояние машины |
| `mtr УЗЕЛ` / `ping УЗЕЛ` | трассировка / ping |
| `discover ПОДСЕТЬ` | обнаружение узлов |
| `dns ИМЯ [ТИП…] [@СЕРВЕР…]` | DNS-запросы, как dig |
| `http URL` | HTTP-запрос с таймингами |
| `services УЗЛЫ [-p ПОРТЫ]` | сервисы и версии |
| `tls УЗЛЫ [-p ПОРТЫ]` | TLS-аудит |
| `proxy ЦЕЛИ [-p ПОРТЫ]` | поиск и диагностика прокси (TCP-connect) |
| `presets [инструмент]` | список пресетов |
| `<команда> --fields` | все поля конфигурации с значениями по умолчанию |

Пресеты применяются по порядку, затем `--config файл.json`, затем цели из командной
строки, затем `--set`. Пароль прокси для `http` и `proxy` — в переменной окружения
`PROXY_SCANNER_PROXY_PASSWORD` (в командной строке его не видно другим пользователям).
Ctrl+C останавливает работу и выводит то, что уже получено.

Примеры:

```bash
proxy-scanner-cli dns example.com MX TXT @8.8.8.8 @tls://1.1.1.1
```

```bash
proxy-scanner-cli dns "_ldap._tcp.dc._msdcs.{domain}" SRV
```

```bash
proxy-scanner-cli mtr 10.10.0.1 --preset "Поиск MTU (VPN, туннели)"
```

```bash
proxy-scanner-cli ping 10.0.0.5 --set cycles=20
```

```bash
proxy-scanner-cli http https://portal.corp.local/ --set proxy_mode=Manual --set proxy=10.0.0.10:3128
```

```bash
proxy-scanner-cli services 10.0.0.0/24 --preset "Windows и AD" --json -o ad.json
```

```bash
proxy-scanner-cli tls 10.0.0.0/24 -p 443,8443 --preset "Только сертификаты" --preset "Закрытый контур"
```

```bash
proxy-scanner-cli proxy 10.0.0.0/16 --preset "Порты: все популярные" -o proxies.csv
```
